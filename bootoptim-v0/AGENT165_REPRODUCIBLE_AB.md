# Agent 165 — reproducible PR #14 physical A/B

This protocol exists to repair the composition error that made the prior PR #10/#14 Windows artifacts unsuitable for physical timing. It does not make a performance claim.

## Immutable sides

The base side is constructed from PR #7 final head `55f05135396e9682a5d0f76a24e62f21850fbc03`, then carries only PR #10's asset-verification-intent contract: `AssetVerificationMode`, fail-closed default propagation, and the existing GUI Start path explicitly using `ModalAction::normal_launch()`. PR #9/160 USN code, PR #8 I/O scheduling work, and unrelated AppCDS changes are not part of the composition.

The candidate side starts at the exact base commit and changes only PR #14's asset-prefix-directory deduplication (`asset_prefix_dirs.rs` plus the corresponding `do_asset_objects_load` call-site replacement). Hash decoding, object paths, SHA-1 verification, repair/download behavior and semaphores remain stock-equivalent.

Each CI artifact contains `COMMIT.txt`, `SHA256SUMS.txt`, the packaged `BootOptimPandora.exe`, the AppCDS interposer, and the JSONL generated by executing the packaged EXE's probe-contract selftest. Artifact names include the exact Git commit SHA.

## Packaged probe gate

Before upload, the Windows workflow executes `BootOptimPandora.exe` through its existing internal helper-command entrypoint with a selftest sentinel. The executable uses the real bridge launch-probe writer and the real `PandoraCommand::spawn` probe path against a disposable copy of `cmd.exe` named `java.exe`; no Minecraft instance or network is involved.

The workflow rejects the artifact unless:

- the first non-empty JSONL record is exactly the `launcher_pre_java` root `begin`;
- there is exactly one root begin and exactly one root end;
- `java_spawn` is one complete observed span and ends before the root ends;
- no event uses the legacy `inclusive_end` form;
- `classpath_resolution`, `native_extraction`, and `wrapper_arguments` are each explicitly `unobserved` rather than represented by an inferred inclusive duration;
- each assets/libraries/java-runtime phase is either one valid observed begin/end pair or one explicit `unobserved` record, and at least one of those phases is actually observed.

Binary string presence is not accepted as evidence.

## Laptop A/B procedure

Use the same `BootOptimLaptop` instance and the same launcher/instance configuration for all four runs. For every run set `BOOTOPTIM_APPCDS_MODE=plan`. Do not set `BOOTOPTIM_VERIFY_IO_LIMIT`. Do not set `BOOTOPTIM_ASSET_USN_CACHE`. Use the interposer shipped in the matching artifact and do not substitute a different build.

Create a new, empty `BOOTOPTIM_LAUNCH_PROBE` JSONL path for every run; never append one measurement to another. Run in this exact order:

1. base
2. candidate
3. base
4. candidate

For each launch, allow the launcher to continue until the Java/Minecraft window has appeared. Only then may automation close the run. Do not autoclose at launcher modal completion, process creation, or any earlier surrogate.

Before calculating Start→Java for a run, validate the JSONL contract: the root begin must be the first event, the root end must be unique, children must lie within the root, the legacy `inclusive_end` representation must be absent, and optional unobserved phases must be explicitly marked as such. A run that fails the contract is invalid and must not enter the A/B calculation.

Use `launcher_pre_java.begin` → the valid root end as the launcher Start→Java interval defined by PR #7. Preserve the raw JSONL and record the artifact SHA-256 and commit alongside each run.

No time saving, regression, or neutral-performance conclusion may be stated until all four physical runs have passed the probe-contract validation. Hosted CI proves composition and packaged behavior only; it is not physical performance evidence.
